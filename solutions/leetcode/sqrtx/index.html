思路

🔗 最初的思路

根据题目，我们需要找到一个数 n ，恰好这个数的 后一个数 n + 1 的平方大于 x，且这个数 n 的平方小于等于 x。根据此题意，且数轴天然有序，所以考虑二分查找。

❌ 你的思路大方向是对的（利用单调性进行二分），但是你的代码存在两个严重的致命问题，这会导致提交失败（Runtime Error 或 Wrong Answer）。

  1. 致命问题一：整数溢出 (Integer Overflow)题目中 $x$ 的最大值是 $2^{31} -1$（约 21 亿）。当 mid 接近 46341 时，mid * mid 就会超过 int 的表示范围（约 21.47 亿），导致溢出变成负数。修正：计算平方时必须强转为 long long，或者使用除法 mid > x / mid 来代替乘法比较。

  2. 致命问题二：逻辑漏洞 (Wrong Answer on exact square)你的判断条件 (nxt * nxt) < x 过于严格。

反例：输入 x = 4。l=0, r=4, mid=2, nxt=3。

  1. l=0, r=4, mid=2, nxt=3。mid*mid (4) 不小于 4，进入 else，r=2。

  2. l=0, r=2, mid=1, nxt=2。11 < 4 (True) 且 22 < 4 (False，因为 4 等于 4)。条件不成立，进入 else，r=1。

  3. 循环结束，返回 1。 错误：4 的平方根应该是 2，你返回了 1。

⭐ 更好的二分策略：寻找“满足 $k^2 \le x$ 的最大 $k$”我们不需要同时判断 mid 和 mid+1，只需要判断 mid。如果 $mid^2 \le x$：说明 mid 可能是答案，但也可能还有更大的，先记下 mid，然后尝试向右找 (l = mid + 1)。如果 $mid^2 > x$：说明 mid 太大了，答案肯定在左边 (r = mid - 1)。

  1. 从 1 开始，避免 mid = 0 导致除零错误

  2. 核心修改：注意这里多了一个 +1

这使得 mid 向上取整。当 l=2, r=3 时，mid = 3，而不是 2

如果你的逻辑是 r = mid - 1 和 l = mid （试图保留左边）：mid 必须向上取整 (+1)。

如果你的逻辑是 r = mid 和 l = mid + 1 （试图保留右边）：mid 正常向下取整。

// ⭐ 更好的二分策略：寻找“满足 $k^2 \le x$ 的最大 $k$”我们不需要同时判断 mid 和 mid+1，只需要判断 mid。如果 $mid^2 \le x$：说明 mid 可能是答案，但也可能还有更大的，先记下 mid，然后尝试向右找 (l = mid + 1)。如果 $mid^2 > x$：说明 mid 太大了，答案肯定在左边 (r = mid - 1)。
class Solution {
public:
    int mySqrt(int x) {
        if (x == 0) return 0;
        
        // 1. 从 1 开始，避免 mid = 0 导致除零错误
        int l = 1, r = x;
        
        while (l < r) {
            // 2. 核心修改：注意这里多了一个 +1
            // 这使得 mid 向上取整。当 l=2, r=3 时，mid = 3，而不是 2
            int mid = l + (r - l + 1) / 2; 
            
            if (mid <= x / mid) {
                l = mid;       // 因为 mid 可能是解，所以保留 mid
            } else {
                r = mid - 1;   // mid 太大了，肯定不是解
            }
        }
        // 如果你的逻辑是 r = mid - 1 和 l = mid （试图保留左边）：mid 必须向上取整 (+1)。
        // 如果你的逻辑是 r = mid 和 l = mid + 1 （试图保留右边）：mid 正常向下取整。
        return l;
    }
};
